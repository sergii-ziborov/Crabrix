# Course delivery

The authored corpus, schema, exporter, parity report, seven course archives, and optional Examples archive live in [crabrix-courses](https://github.com/sergii-ziborov/crabrix-courses). The app keeps the original seven signed 1.0.1 packs only as offline migration resources for existing learners. New installs use the signed public catalog; its URL is `https://raw.githubusercontent.com/sergii-ziborov/crabrix-courses/main/catalog.v1.json`, with descriptors and archives served by GitHub Releases.

The separate Examples CoursePack contains 46 Academy projects under `library-projects/`, including a README for every project. Learn labels it **Code Examples** and offers one optional download, independent of Cargo & Real Projects. Its 46 stops are all open: selecting one shows a short description and source preview, then **Open in Code** copies its files into the durable ProjectStore with a new ProjectID and the Examples pack version. There are no answer, score, or progression gates for these stops. Deleting the download leaves the project copy intact. Older installed Projects 1.0.1 packs still expose their gallery until the learner chooses the separate Examples download. The source files are not Swift literals or separate compiled catalogs in the app target. Six Canvas examples use the same general Canvas renderer as user projects.

## Format and trust

The catalog and each descriptor use Ed25519 over the exact payload bytes with different domain prefixes. The built-in public keyring verifies them. Catalog entries name exact descriptor/archive hashes; the descriptor names the ZIP hash and version. Each ZIP manifest lists payload paths, lengths, and SHA-256 values, with no self hash. A repeated `(courseID, language, contentVersion)` with a new digest and a network sequence rollback are rejected.

`CoursePackVerifier` rejects extra or missing payload files, unsafe paths, links, path collisions, forbidden executable payload roles, excessive entries, and byte limits. `CourseInstaller` copies to same-volume staging, streams extraction with a second digest check, writes a journal, then atomically replaces the active-version index. Recovery retains the old pointer after an interrupted activation. Installed packs are under Application Support and excluded from backup as replaceable resources; user work is elsewhere.

The network client accepts the signed catalog from `raw.githubusercontent.com`. Archive transfers start at `github.com` and allow redirects only to `release-assets.githubusercontent.com` and `objects.githubusercontent.com`. It limits accepted bytes to the signed catalog size and verifies hashes. An interrupted archive leaves a digest-keyed partial file and transfer record in the purgeable cache; a later download requests the missing HTTP byte range. If the host ignores Range, the full response replaces the partial before hash verification. New learners open **Learn** directly to a compact list of downloaded and available courses; existing learners use the Courses entry. Each available row has a Download button and exact size; the confirmation precedes transfer. Progress, Pause, and Resume stay with that row. A transfer error leaves the prior course active. The signed baseline catalog is bundled, so the initial list opens without fetching a catalog over the network. After a successful refresh, the accepted signed catalog is cached and is shown again on an offline launch.

Both Learn and My Courses check for updates when opened, and expose a manual refresh button and pull-to-refresh. The app chooses the newest compatible entry per course, ignoring a release that needs a newer app or unsupported capability. Installed courses with a higher published content version display a direct **Update** button; **Update all** processes those downloads one at a time after showing their combined size. Each transfer is verified and activated independently. The previous version stays active if its replacement fails, while learning progress and project copies remain outside the replaceable CoursePack tree. An open lesson retains its original snapshot until the learner leaves it. Publishers must bump `contentVersion` when changing an existing lesson; a signed catalog will not replace the bytes of an already published version.

## Offline migration

The previous binary is absent after an iOS app update. For that reason, all seven transition packs are resources of the new binary. Before the current progress store can write its schema, the app persists a first-launch decision from existing progress, lesson evidence, or project files. An existing learner gets all seven packs verified and activated locally without an old bundle lookup or network connection. A clean install activates none: all seven courses appear in the list, and the learner chooses which to download. Already installed newer course versions are not downgraded. A lesson retains its content snapshot while open. Quick Practice, Code Recall, and Term Train snapshot only installed course content when a round starts; an update cannot change a question or answer mid-round.

The row menu removes an installed copy from Application Support without deleting projects or progress. A one-time baseline activation marker prevents the next launch from silently reinstalling a course the user removed; a previously opened lesson retains its decoded content snapshot, including the validator used by the compiler. A mocked connection interruption followed by manager recreation, and a live public release Range request from a persisted partial, passed on Simulator. A real process-kill transfer gate and crash injection at every installation boundary are still pending. Legacy aggregate progress is attributed to the fixed 142-lesson baseline; all current lesson, practice, and project data comes from installed CoursePacks.
