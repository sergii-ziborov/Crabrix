# Local Git — stage 3A qualification

The local foundation is now extended by the separately qualified
[HTTPS and complete-portability candidate](git-https-portability-2026-10-28.md).
The boundaries below record the original 3A profile.

This candidate is separate from App Store Connect 1.1.3 (113). Build 113 contains
the reliability and Rust Test/Format deliveries; it does not contain Git.

The existing project settings open **Local Git**: Changes, History and Branches.
Initialize explicitly, select changed files, enter an author/message and commit.
Autosave protects the current project independently; it never creates commits.
History offers a file preview and a separate explicit Restore action. Switching
branches requires a clean tree and leaving any live Playground first. The
existing editor, keyboard dock and Duo layout are not redesigned.

## Storage and concurrency

`Vendor/CrabrixGitCore` builds official libgit2 1.9.7 from 211 pinned C translation
units, using Apple SecureTransport, system zlib/iconv and collision-detecting SHA-1.
It does not spawn a command-line Git process, execute hooks, or require an account.
The original source tar, generated configuration and dependency notices are pinned
in `upstream-manifest.json`. `scripts/verify_git_core.py` checks originals and the
complete offline source export; bootstrap refuses stale copies.

A project has a separate standard Git object/index/ref store and complete
canonical worktree. Text-project save/replacement never removes its Git history.
Non-UTF-8 files, hidden files and executable modes remain in that worktree.
Every mutation operates in a disposable full copy and installs objects, index,
refs, worktree and ownership metadata together. A previous root is retained for
interrupted replacement recovery. Explicit revisions reject stale editor mirrors;
commit/branch/checkout also check the expected HEAD.

Background snapshots permit typing. A finished commit records its captured source;
newer typing remains uncommitted and requires Refresh. Checkout and Restore use
the existing exclusive project-operation boundary. A stale Restore preview cannot
overwrite newer text. Git results do not become compiler results or learning
evidence. Deleting a project cancels/waits for its Git job and pending saves.

## Initial profile and boundaries

- Editable project: 2,048 files, 2 MiB per file, 16,000,000 UTF-8 bytes total.
- Complete canonical worktree: 8,192 files, 8 MiB per file, 64 MiB total.
- Git storage: 192 MiB, 32,768 filesystem entries. Existing roots are never
  automatically evicted when these bounds are exceeded.
- Case/Unicode aliases, file-directory collisions, traversal, filesystem links,
  special files and invalid paths fail before replacing current data.
- Status reports modified/untracked/deleted paths; diff is a bounded text preview.
  Separate imported staging is refused instead of silently replaced by the
  selected-file commit model. A full commit ID is required for historical reads.
- History shows the latest 50 commits; local branches are bounded to 256.
- An old source ZIP/snapshot starts a new history; no missing parents are invented.
- Current `.crabrixproject` and source ZIP exports remain text-project formats.
  This candidate does not yet claim full repository import/export, private access,
  fetch/pull/push, binary-resource compilation, LFS, submodules or rebase.
- Shared transmits editable source only. Neither objects nor Git identity secrets
  are added to the collaboration protocol.

Terminal and UI call the same service. Supported local commands are `git init`,
`status`, `diff <path>`, `log`, `branch [name]`, `switch <name>`,
`commit -m "message" -- <paths>`, `show <full-commit>:<path>`, and
`restore --source <full-commit> -- <path>` (opens a preview). Use quoted names:
`git config user.name "Ada Lovelace"`; `git config user.email ada@example.com`.
Unknown options and unimplemented Git commands report their boundary explicitly.

## Evidence

`build/git-20261028/` retains the actual C Simulator probe, desktop interoperability
checks, Swift service tests, native project integration, UI runs and diagnostics.

- Three macOS Swift service tests exercised real commits, selected paths,
  standard desktop `git fsck --full`/clone, hidden/deleted/binary files and modes,
  branches, dirty checkout refusal, history reads, competing actor revisions,
  stale HEAD, interrupted root recovery, unsafe and oversized worktrees.
- Four native iOS Simulator integration tests exercised project save/reopen,
  branch replacement, source diff, history/Restore, stale previews, background
  typing, terminal identity/commit, and deleting during initialization.
- Final native gate: all ten cases passed, including the four integration cases
  and six offline-license/inventory cases. All 1,829 notice groups decode from
  the actual app bundle.
- Two UI cases passed on each Simulator: iPhone confirmed terminal identity/init,
  selected commit, History, source preview and unchanged editor, then actual touch
  typing. iPad confirmed the same Git flow and the existing real Debug/web-resource
  breakpoint and offline preview. [Phone commit](screenshots/git-local-phone-commit-20261028.png),
