# Compiler toolchain

The current app input is the older pinned Weblings `artifacts-test-7` WASI compiler and sysroot. [`Crabrix/Resources/toolchain.lock.json`](../Crabrix/Resources/toolchain.lock.json) is the app's release input for its compiler version, source asset URLs, target, and expected SHA-256 digests. [`scripts/toolchain_manifest.py`](../scripts/toolchain_manifest.py) validates it before the build Mac fetches and packages the assets. Cargo cache identity and the in-app version label read the same bundled manifest. The phone never downloads a compiler update. This input is a compatibility baseline for the WasmKit 0.4.1 integration.

[crabrix-toolchain](https://github.com/sergii-ziborov/crabrix-toolchain) is a public fork of the original builder recipe with exact source and bootstrap locks, validator, fetch/build/package/verify commands, notices, and reproducibility documentation. The matching prebuilt CI LLVM archive for the selected Rust revision returned 404, so the builder compiles LLVM from the pinned Rust submodule and enables both LLVM and Cranelift. The Cranelift-only trial exposed 1,569 unsupported code-generation stubs. Source patches cover narrow integer conversions, high-half multiplication, i128 byte swap and the float-to-i128 return ABI. The completed Linux amd64 Docker image is now pinned and [publicly archived](https://github.com/sergii-ziborov/crabrix-toolchain/releases/tag/build-env-2026-10-02). A clean release build is in progress; there is **no signed Crabrix-built compiler release** yet.

The controlled Docker image ID is `sha256:b82320d0f0c28f7ae2b0cacfad950582da63bee178715e5d8fa93aa5efac48b1` (Linux amd64). On this Apple Silicon Mac it runs with x86_64 emulation. Source-built candidates are staged only in unsigned Release Simulator test apps without changing the production manifest. The first compiler passed E0502/repair and all 46 Academy Examples but failed a four-crate CLI at missing `smulhi.i64` lowering. The second passed checked multiplication and a real `smallvec` crate but failed that CLI later at `bswap.i128` in `regex-automata`. Later candidates passed the exact byte-swap regression, standalone `regex`, the three-file `clap`/`regex`/`hashbrown`/`smallvec` CLI, all 46 Examples, and the multi-file route planner with `petgraph` and `itertools` in separate iOS 18.2 Release Simulator runs. See [candidate test results](toolchain-candidate-simulator-gate.md) and the [fifth-candidate report](https://github.com/sergii-ziborov/crabrix-toolchain/blob/codex/toolchain-narrow-casts-2026-10-01/docs/candidate-v5-compatibility.json) for hashes and gates. This is measured compatibility for those workloads, not proof that arbitrary crates compile.

The app manifest still describes the old verified tar/zstd release. The build scripts now accept a second `crabrix-release-v1` source kind: the build Mac verifies an Ed25519 descriptor against a public key kept in the app repository, checks exact asset hashes and the complete sysroot inventory, then stages the ZIP unchanged for bundling. This path has unit tests but has not yet been used for an app release. Promotion still requires the clean compiler build, two-build comparison or difference report, artifact notices, protected signing, the same Simulator and device gates, and an updated pinned app manifest. A compiler candidate cannot replace the app's release input by editing the manifest alone.
