# Compiler toolchain

Crabrix 1.1.8 build 135 selects [`crabrix-rust-2026-11-07.1`](https://github.com/sergii-ziborov/crabrix-toolchain/releases/tag/toolchain-2026-11-07.1). Rust remains `1.96.0-dev`, targeting `wasm32-wasip1`. The [app input manifest](../Crabrix/Resources/toolchain.lock.json) pins the compiler, matching sysroot, inventory, signed descriptor and source recipe. Downloads and signature verification happen on the build Mac; the signed app contains the compiler data.

The compiler SHA-256 is `27acccf94e1f4083b311b352164fe1a310077c76f4cd3e221a2ee26b02309008`. Recipe `0a5970c97ef0e192c8f6e5dec460190924489f97` fixes atomic loads, stores and read-modify-write operations at their actual 8/16-bit widths, preserving adjacent fields. It also supplies the complete source-built WASI macro sysroot. The signed `proc-macro-rpc-v1` capability enables locally compiled WASI procedural macros, including Serde derive. Host dylibs and arbitrary host processes are outside this profile.

This release uses the explicit [Mac qualification profile](https://github.com/sergii-ziborov/crabrix-toolchain/blob/main/release-profiles/macos-wasi-rpc-fat-2026-10-25.json), separately from the earlier Linux recipe. Independent Xcode Cloud source builds 89 and 90 produced identical raw compiler, sysroot ZIP and inventory bytes. Their original candidate provenance is embedded unchanged in the release record. Qualification requires executed optimized Release Simulator gates, adjacent-byte atomic canaries, unchanged identity macros, real Serde derive and the full 32-package Kameo graph. The XCTest host explicitly enables legacy course fixtures for migration audits; distribution archives leave that test-only condition empty.

On arm64 the app uses CrabrixRuntime's software-bounds direct interpreter with memory, fuel, output and cancellation limits. Token dispatch is retained for control tests. No native AOT compiler experiment is enabled. Simulator results do not establish a physical-device timing or the separate 30-second large-project goal.

Primary and vendored notices are byte-identical to the earlier release: the Rust, WASI and vendored source revisions remain pinned. The new descriptor signs their exact hashes again, together with compiler/sysroot identity and qualification evidence. Old compiler/cache identities are retained separately; only the selected toolchain is packaged into the app.

## Earlier Linux release

Crabrix 1.1 build 21 pins the public [Crabrix source-built toolchain release](https://github.com/sergii-ziborov/crabrix-toolchain/releases/tag/toolchain-2026-10-02.1), `crabrix-rust-2026-10-02.1`. It contains a `rustc.wasm` compiler and `wasm32-wasip1` sysroot built from locked Rust source `abc48c0b8aba37d3f3862a9d5c76eb4e78f90e88` (`1.96.0-dev`). The [app input manifest](../Crabrix/Resources/toolchain.lock.json) pins the release URL, Ed25519 key ID, descriptor digest, source lock, compiler and sysroot digests. The compiler is fetched and verified on the build Mac and bundled in the signed app. An iPhone or iPad does not download compiler updates.

The build recipe is a public fork of [AngelOnFira/wasm-rustc](https://github.com/AngelOnFira/wasm-rustc) with upstream MIT notices and history preserved. The [source lock](https://github.com/sergii-ziborov/crabrix-toolchain/blob/main/toolchain.lock.json) records exact Rust, submodule, backend, WASI SDK, stage0 compiler and Linux amd64 Docker image inputs. This build compiles LLVM from the pinned Rust submodule and uses a verified prebuilt stage0 and WASI SDK. It is a source-built compiler, not a bare-metal bootstrap. Source patches cover narrow integer conversions, high-half multiplication, i128 byte swap and the float-to-i128 return ABI.

The release includes an [Ed25519 signed descriptor](https://github.com/sergii-ziborov/crabrix-toolchain/releases/download/toolchain-2026-10-02.1/toolchain.descriptor.json), per-file sysroot inventory, SHA-256 sums, primary and vendored license notices, provenance, [compatibility results](https://github.com/sergii-ziborov/crabrix-toolchain/releases/download/toolchain-2026-10-02.1/compatibility-results.json) and a [two-build comparison](https://github.com/sergii-ziborov/crabrix-toolchain/releases/download/toolchain-2026-10-02.1/reproducibility-results.json). A public download of every release asset passed the independent verifier. The two clean builds had different raw digests; the report localizes differences, and the release is described as source-pinned rather than byte-identically reproducible. The signing key stays outside all public repositories and the app; the built-in public keyring authenticates the descriptor.

On the pinned CrabrixRuntime and iOS 18.2 Release Simulator, the release compiler passed 13 selected gates: Check, Run, E0502, root features, offline pin, Vendor, all 46 Academy Examples, a three-file CLI using `clap`, `regex`, `hashbrown` and `smallvec`, a route planner using `petgraph` and `itertools`, Stop, bounded output and warning-cache parity. A separate `serde_json` probe failed because the supported Cargo subset does not execute build scripts and `serde_core` needs generated `OUT_DIR` content. The exact tests, artifact IDs and failed probe are in the compatibility report. These are selected Simulator gates; arbitrary crates and physical-device performance are not implied.

`./scripts/bootstrap.sh` validates the app manifest, fetches the public release over HTTPS, verifies the descriptor signature and exact asset hashes, checks every sysroot ZIP entry against its signed inventory, and stages the files for Xcode. `scripts/package_toolchain.py` copies the verified compiler and ZIP into app resources. Cargo cache identity and the Settings version label use the bundled manifest. CoursePacks can include editable source and `Cargo.toml`, but cannot replace the compiler, sysroot or runtime. [Runtime integration](runtime-integration.md) records the separate WasmKit-derived engine revision and its measurements.

The bundled WASI sysroot has no host `libproc_macro`. Build 21 therefore selects parser-only features for `syn`, `quote`, and `proc-macro2` when added from the package catalog. A plain `syn` entry created by an older build can be repaired in the project package panel. The Release Simulator gate built these source crates and ran a program using `syn::parse_str`; procedural macro crates remain unsupported.
