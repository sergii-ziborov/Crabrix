# Compiler toolchain

The current app input is the older pinned Weblings `artifacts-test-7` WASI compiler and sysroot. [`Crabrix/Resources/toolchain.lock.json`](../Crabrix/Resources/toolchain.lock.json) is the app's release input for its compiler version, source asset URLs, target, and expected SHA-256 digests. [`scripts/toolchain_manifest.py`](../scripts/toolchain_manifest.py) validates it before the build Mac fetches and packages the assets. Cargo cache identity and the in-app version label read the same bundled manifest. The phone never downloads a compiler update. This input is a compatibility baseline for the WasmKit 0.4.1 integration.

[crabrix-toolchain](https://github.com/sergii-ziborov/crabrix-toolchain) is a public fork of the original builder recipe with exact source and bootstrap locks, validator, fetch/build/package/verify/smoke commands, notices, and reproducibility documentation. The matching prebuilt CI LLVM archive for the selected Rust revision returned 404, so the candidate builds LLVM from the pinned Rust submodule and enables both LLVM and Cranelift. The Cranelift-only trial exposed 1,569 unsupported code-generation stubs. Source patches cover narrow integer conversions, high-half multiplication, and i128 byte swap; an attempted stage1 Cranelift installation patch was removed after proving incompatible with this fork. The release build environment image digest remains unset; release validation fails closed. There is **no signed Crabrix-built release** yet.

The local Docker candidate uses four x86_64-emulated CPUs and 9 GiB of RAM on an Apple Silicon Mac. It has produced two source-built `rustc.wasm` candidates and the WASI sysroot; the app's unsigned Release Simulator test host stages them without changing the production manifest. The first compiler passed E0502/repair and all 46 Academy Examples but failed a four-crate CLI at missing `smulhi.i64` lowering. The second passed checked multiplication, `smallvec`, Vendor, offline pin, E0502, root features, Stop, and memory-limit gates; the same CLI failed later at `bswap.i128` in `regex-automata`. A third source build with that backend patch is underway. See [candidate test results](toolchain-candidate-simulator-gate.md). These are measured compatibility gates, not proof that arbitrary crates compile.

The app manifest still describes the old verified tar/zstd release. Promoting a source-built candidate requires a pinned build environment, two-build comparison, signed descriptor, raw artifact fetch integration, notices, and successful Simulator and device gates. A compiler candidate cannot replace the app's release input by editing the manifest alone.
