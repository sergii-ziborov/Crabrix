## MCP-01 — поставленная первая версия и дальнейший контракт через Shared

MCP 0.1.1 опубликован в npm и на сайте с одинаковыми архивами; [проверка установки и public SDK flow](../playground-mcp-npm-2026-10-29.md). Он использует общий проект как явно подключённый участник с видимым именем. Первая версия подтверждает чтение кода, conditional edits, выделения, TTL, view-only и owner closure; Run/Debug остаются локальными действиями пользователя. Ниже — целевой дальнейший контракт; discovery клиента, диагностика и execution permissions ещё не реализованы.

- Discovery: профиль устройства/браузера, версии, ограничения и доступные
  операции из реестра возможностей. Публичный `/api/capabilities` возвращает
  только метаданные продукта; это ещё не MCP endpoint.
- Read: дерево допустимых файлов, конкретный текст, текущая версия, выделение,
  диагностика и состояние активной операции. Git secrets, Keychain, `.git`,
  пакеты и файлы вне комнаты не входят в доступ.
- Edit: набор правок к точно указанной версии. Несовпадение версии возвращает
  конфликт с новой версией, без перезаписи чужого изменения. Авторство и
  выделение передаются обычным Shared-протоколом.
- Check/Build/Run/Debug: команды направляются в подключённый клиент. Он сообщает
  собственные возможности и исполняет локально только в рамках явно выданного
  разрешения. Получение ссылки и правки сами по себе ничего не запускают.
- Временная жизнь: действующие лимиты комнаты — четыре участника, 16 файлов,
  64 KiB на файл, 128 KiB суммарно; час по умолчанию, максимум 24 часа. Лимиты
  локального редактируемого проекта и Cargo — отдельные величины.
- Доступ к plaintext для GPT/инструмента выдаётся отдельно и явно. Relay
  сохраняет модель ciphertext в RAM; ключи не помещаются в query, логи,
  аккаунт или Git. При реализации выбрать и проверить доверенную границу
  расшифровки, OAuth/permission model, отзыв доступа и удаление ключей по TTL.
- Save to Crabrix остаётся явной клиентской операцией. MCP не превращает
  временную комнату в постоянное хранилище и не делает автоматические push.

Приёмка MCP: web↔MCP, app↔MCP и два клиента↔MCP; конфликт одновременных правок;
read-only ссылка; отозванный/истёкший доступ; выделение с Unicode; Stop и
переключение проекта; отсутствие backend execution и утечки секретов. Требования
конкретного GPT-клиента и актуальной MCP-спецификации сверяются перед реализацией.
