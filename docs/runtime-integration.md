# Runtime integration

The public [CrabrixRuntime fork](https://github.com/sergii-ziborov/crabrix-runtime) keeps WasmKit upstream history and notices. Its base is WasmKit 0.4.1 at `a0471eaee817c523b8023d8ebb1c70ff70b7950a`; the app pins fork commit `719f94d7d27368549502828217e3dbc7e6738852`. There is no second production engine in the SwiftPM graph. The old vendored source remains only as historical source in the repository and is not linked into the app target.

`RustcRuntime` uses token threading, software memory bounds checks, upstream fuel metering, the fork's cancellation probe at fuel checkpoints, and a fresh `Store` and WASI instance for each invocation. Host calls are guarded, and network socket imports return guest `ENOSYS`. Separate `CompilerHostPolicy` and user program policy set memory, table, fuel, wall-clock, and output budgets. A fuel trap maps to a typed instruction-budget stop. The compiler and program each receive a write-time WASI stdout/stderr budget (16 MiB and 1 MiB respectively). The program's writable sandbox also has a quota monitor.

The fork adapter tests cover fuel exhaustion, pure-loop cancellation, fresh-run recovery, memory page limits, guarded WASI links, read-only nested descriptors, and the shared output budget. On the pinned remote revision, the app's six sandbox policy tests, bundled E0502 Check, repaired Run, multi-file Run, and a user-program output stress test passed on iOS Simulator with the old pinned toolchain. See [validation](VALIDATION.md) for what was actually run.

## Remaining gates

Compiler source, sysroot, and registry preopens use read-only WASI rights; `/work` and `/tmp` remain writable outputs. Check cache hits retain their full diagnostics and spans, with a bounded in-memory snapshot cache; the [simulator comparison](performance/2026-09-30-warning-check-simulator.json) records this fix and the limited speed evidence. `RustcRuntime` parses bundled and cached modules through WasmKit's file reader, avoiding a full `Data` to `[UInt8]` conversion; [the five-run parser/dispatch probe](performance/2026-09-30-file-parser-dispatch-simulator.json) records unchanged Check correctness and limited speed observations. Parsed student-program modules now have an eight-entry LRU with a 64 MiB admission budget based on four times the Wasm file size; memory warnings queue eviction after the active compile. This is a cost proxy, not an RSS guarantee. Persisting program artifacts copies the file without loading it into a second whole-file `Data` buffer. The separately cached bundled compiler module remains available after program-cache eviction. Direct dispatch remains disabled pending the full Run/Cargo/device gates. Cold host parse cannot currently be stopped in the middle of parsing. Compiler workspace/tmp disk quotas, device measurements, and physical memory-pressure recovery still need evidence. Do not interpret the existing fuel tests as proof of these separate properties.
