Build 105 adds a local source-instrumented Rust debugger and a one-hour default sharing lifetime. It retains optional temporary source sharing for education and live interviews. The app remains an offline Rust compiler with no account requirement. https://crabrix.com/playground/ is public. Website Academy accounts are separate. Release is manual.

Open a project’s actions and Share Playground. Create a 1/4/12/24-hour room (one hour by default), copy its edit link, then open it in a browser or another updated Crabrix app. Edits, cursors and selected ranges synchronize. Received source is visible/editable and never runs automatically; press Run explicitly. Save a local copy before expiry. External HTTPS Universal Links and the explicit Open in Crabrix action are supported.

Clients encrypt text with AES-256-GCM; keys stay in URL fragments. The relay cannot decrypt source. Bounded ciphertext is kept in RAM only, never in accounts, files, database or backups, and expires within 24 hours. Restart can end sessions early. Limits: four participants, 16 text files, 64 KiB/file and 128 KiB/project. No images or dependency archives are shared. App Run uses the bundled WASI compiler locally; website Run uses a client-side Worker with standard library/local modules. No backend compilation, remote shell or downloaded native executable. Debug is local: in project settings choose Debug Rust project, tap line numbers for breakpoints, use step controls and Inspect debugger state. A bundled Rust parser instruments a separate source snapshot. The bundled compiler compiles it; its Wasm checkpoints pause only the interpreter queue. The parser does not evaluate user code as JavaScript. Debug supports synchronous source statements and safe primitive locals, without async/const body, macro-internal or aggregate inspection. The guide states these limits.

Browser source preparation retained from build 101:
Explicit npm install/ci acquires the imported browser source graph from the public npm HTTPS registry, checks archive integrity and saves modules, manifests and original license texts as editable project files. Run and Check never fetch packages.

Reproduce: import https://crabrix.com/examples/offline-browser-dashboard.zip in Crabrix. In Terminal enter npm install while connected. Disconnect and press Run or enter npm run dev. The React/TanStack Query/Zustand/Zod dashboard uses local data; Count updates local state. All imported source is visible in Files. Guide: https://crabrix.com/guide/#browser-packages.

Supported npm commands map to Crabrix browser operations, not arbitrary scripts, lifecycle hooks, Vite/Node/Bun, native addons or server processes. TypeScript syntax is transpiled without type checking. Trusted compiler/builder tools are bundled. Text is transformed on a serial JavaScriptCore worker, where user plugins/programs are not evaluated. Generated code executes in the existing nonpersistent WebKit preview with a bounded immutable asset snapshot, CSP and external requests blocked. It has no shell or native project-writing bridge. Downloaded libraries do not extend the native app.

Rust remains in the existing local WASI sandbox. Compiler/runtime acceleration and the 2,048 Cargo-package ceiling are retained. Existing Duo, dock and keyboard geometry are preserved. Full original licenses, Privacy and Terms are available offline in Settings and on the website. Guest collaboration is an explicit optional network operation.
