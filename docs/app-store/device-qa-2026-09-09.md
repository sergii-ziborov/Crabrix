# Device QA fixes — 1.0 (7)

The owner reported three issues while testing build 6 on an iPhone before
recording the walkthrough requested by App Review under guideline 2.1.

## Changes

- The diagnostic shortcut now uses only the latest compilation result. A new
  build clears the prior error prompt, and a successful run keeps it cleared
  even when the lesson's expected output or other evidence is still missing.
  Diagnostic history used to validate repair lessons remains separate.
- File navigation is available during Check and Run. Loading another editor
  buffer does not advance the workspace revision, so the compilation result
  is retained. Actual edits still invalidate results from an older snapshot.
- Crate source enumeration and reading normalize filesystem aliases before
  computing relative paths. On iOS, `/var` and `/private/var` may refer to the
  same container. The prior substring replacement produced an invalid path
  such as `/private/.cargo_vcs_info.json`, falsely blocking ordinary packages.
  Source-integrity fingerprints use the same normalized relative paths, so a
  cache moved from staging remains valid under either container alias.
  Existing downloads are checked again on the next Resolve or Run; any stale
  completion marker is repaired from the checksum-verified archive.
- The Packages panel lists direct dependencies with a Remove button, even
  before resolution succeeds. Removal preserves other manifest text, handles
  Cargo aliases and table declarations, cleans feature references, and
  refreshes the lockfile including after the last dependency is removed.
  Transitive packages leave the project graph when no longer required; shared
  cached sources and user-authored vendor files are retained.
- Removed the internal “Physical device gate” QA note from the sidebar.
